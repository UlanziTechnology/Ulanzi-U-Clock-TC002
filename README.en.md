# Ulanzi U-Clock TC002

Official open-source development resources for the Ulanzi TC002 pixel clock. This repository is aimed at developers who want to build on top of the TC002 and provides a complete FlyThings IDE usage guide, a platform SDK sample project, and runnable demos for every hardware peripheral.

> For usage instructions and community firmware, please visit the product's official page; this repository is **focused solely on how to write, build, and flash code onto the TC002**.

## Hardware Overview

| Item | Specification |
|---|---|
| SoC platform | Z21 series (Linux-based) |
| Display | 52 × 16 full-color RGB LED matrix, SPI-driven |
| Input | 1 rotary knob (CW / CCW / press) + 3 independent buttons |
| Audio | Built-in speaker, supports MP3 playback, volume levels 0–6 |
| MIC | Volume data reported by the MCU |
| Wireless | Wi-Fi + BLE (BLE requires Wi-Fi to be enabled) |
| User GPIO | `GPIO_06` and `GPIO_85` reserved as LED pins |
| Upgrade port | USB-C, with a forced-recovery button next to it |

## Quick Start

### 1. Install the FlyThings IDE

Download and install [FlyThings IDE](https://download.s21i.co99.net/14731609/0/0/ABUIABBPGAAglMLczgYo0Mjk3AU.zip?f=flythings-ide-win32-win32-x86-zkswe-setup.zip&v=1775706403) (Windows).
See [`IDE使用说明/说明文档.md`](IDE使用说明/说明文档.md) for the full installation and interface guide.

### 2. Import the Sample Project

`File` → `Import` → `General` → `Existing Projects into Workspace`, browse to `Z21_TC002_Demo/`, and confirm to complete the import.

### 3. Build

Select the project, then build with the keyboard shortcut `Ctrl + Alt + Z`, or click the green triangle button on the toolbar.
Build artifacts are written to `Release/`.

### 4. Flash and Debug

The TC002 has built-in Wi-Fi, and **ADB debugging is only available over Wi-Fi** (the USB data port operates in USB-drive mode):

1. Connect the device to the same LAN as your computer and note its IP address.
2. In the IDE, go to `Debug Configurations` → `ADB Configurations` → select **WIFI** and enter the IP.
3. Right-click the project → `Download & Debug`, or press `Ctrl + Alt + R`.

Download-and-debug runs in RAM and **is not persisted** — it reverts after a power cycle. To persist changes, use `Image Build` to produce an `update.img`, copy it to the root of a FAT32-formatted TF card, insert the card, and power on to trigger the upgrade.

### 5. Restore the Official Firmware

Hold the reset button next to the USB-C port while powering on; the device automatically reflashes the official firmware.

## Key API Reference

The table below lists only the high-level APIs already wrapped by the sample project. Low-level platform APIs (`EASYUICONTEXT`, `UARTCONTEXT`, `StoragePreferences`, `TimeHelper`, etc.) are documented in the IDE guide.

### LED Display

```cpp
// 52 * 16 pixels, 3 bytes RGB per pixel, row-major
uint8_t rgbData[52 * 16 * 3];
PageBase::sendLedData(rgbData);   // Throttled internally; frame interval >= 15 ms
```

### Key Events

```cpp
#include "managers/KeyManager.h"
KeyManager::getInstance().addKeyEventCallback([](int code){
    // E_KEYCODE_CLOCKWISE / ANTI_CLOCKWISE / KNOB_BUTTON
    // E_KEYCODE_LEFT_BUTTON / MIDDLE_BUTTON / RIGHT_BUTTON
});
```

### Audio Playback

```cpp
#include "managers/AudioManager.h"
auto& audio = awtrix::AudioManager::getInstance();
audio.setVolume(3);                  // 0–6
audio.playAudio("/path/to/file.mp3");
audio.pauseAudio(); audio.resumeAudio(); audio.stopAudio();
```

### MIC Volume

```cpp
#include "managers/McuManager.h"
McuManager::getInstance().setAutoMicReport(true);
int mic = McuManager::getInstance().queryMicValue();
```

### Wi-Fi and BLE

```cpp
#include <base/wifi.h>
#include "ble/bluetooth_service.h"

base::wifiOnAndWait(10);             // Wi-Fi must be turned on first

BluetoothParams p;
p.name = "Ulanzi TC002 AB12";
p.on_message = [](const std::string& msg) { /* ... */ };
BluetoothService::instance().start(p);
```

Optional: preconfigure Wi-Fi/BLE parameters via the USB drive at `/mnt/usb1/test.cfg`:

```json
{ "ssid": "...", "pwd": "...", "isConnect": true, "ble": "MyName" }
```

If `ble` is left empty, the device name automatically uses the last four hex digits of the MAC address (e.g. `Ulanzi TC002 XXXX`).

### User GPIO

```cpp
#include "utils/GpioHelper.h"
GpioHelper::output("GPIO_06", 1);    // Only GPIO_06 / GPIO_85 are reserved
```

## Development Notes

- **Anti-brick flag**: must be set at the entry point on every boot, otherwise the system will roll back to the official firmware.

  ```cpp
  #include <os/SystemProperties.h>
  SystemProperties::setString("sys.zkapp.state", "running");
  ```

- **MCU initialization must happen before any LED refresh**:

  ```cpp
  McuManager::getInstance().initialize(
      new PixelMcuProto::McuParse("/dev/ttyS1", 1500000));
  std::string ver;
  McuManager::getInstance().queryMcuVersion(ver);
  ```

- **SPI frame rate**: `sendLedData` must not be called with a frame interval shorter than 15 ms. Throttling is built in — just call it directly.
- **BLE depends on Wi-Fi**: confirm Wi-Fi is up before starting BLE.
- **Don't block the UI thread**: callbacks like `onUI_init` / `onUI_Timer` must not perform long-running work, otherwise the "insert card to upgrade" prompt cannot be shown.
- **Do not edit** anything under `src/activity/` — those files are auto-generated by the IDE from the `*.ftu` definitions.

## Community Contributions

Community developers are welcome to submit two kinds of apps to this repository:

- **FlyThings apps** — C++ projects that run on the TC002 device itself. Submit under [`apps/flythings/`](apps/flythings/).
- **MQTT apps** — primarily Home Assistant blueprints; users import them into their own HA instance with one click and control the TC002 over MQTT. Submit under [`apps/mqtt/`](apps/mqtt/) (see [`apps/mqtt/README.md`](apps/mqtt/README.md)).

Full submission rules, directory conventions, and the PR workflow are documented in **[`CONTRIBUTING.md`](CONTRIBUTING.md)**.
