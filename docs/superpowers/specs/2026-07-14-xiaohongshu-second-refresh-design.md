# TC002 小红书扩展秒级刷新设计

## 目标

把 Chrome 扩展的刷新配置从分钟改为秒，允许用户在解压加载模式下选择最短 5 秒周期，
同时保留跨电脑动态配置和旧版本设置迁移。

## 方案

继续使用现有 `chrome.alarms` 调度，不增加持久后台标签、offscreen document 或新权限。
设置页保存 `refreshSeconds`，service worker 以 `refreshSeconds / 60` 设置
`periodInMinutes`。Chrome 官方对普通打包扩展通常限制 alarm 最短 30 秒，但对解压加载扩展
不施加该频率限制；本仓库的安装方式正是“加载已解压的扩展程序”。

## 配置和迁移

- 新字段：`refreshSeconds`。
- 默认值：30 秒。
- 最低值：5 秒；非数字、非有限值或更小值统一归一化为默认值或 5 秒下限。
- 如果 storage 中没有 `refreshSeconds`、但存在旧 `refreshMinutes`，则使用
  `max(5, floor(refreshMinutes * 60))` 生成新值，保存 `refreshSeconds` 并删除旧字段。
- 如果两个字段同时存在，以 `refreshSeconds` 为准并删除旧字段。

迁移在 service worker 安装、启动和调度前执行；options 页面恢复配置时也调用同一语义，
确保用户打开页面时看到秒值而不是旧分钟值。

## 用户界面

设置项名称改为“刷新间隔（秒，最少 5）”，输入框 `min=5`、`step=1`、默认显示 30。
页面提示：5 秒仅建议短期联调；长期运行建议 60 秒以上，以降低小红书登录验证和限流风险。

## 调度行为

保存配置后清除旧 alarm，并立即创建同名 repeating alarm：首次触发约 1 秒后，随后按
`refreshSeconds / 60` 周期触发。浏览器休眠、扩展重载或系统调度可能造成延迟；扩展不承诺
硬实时 5 秒，只保证请求的目标周期为 5 秒。

单次刷新仍依次处理配置主页，避免同时打开大量标签。一个周期仍在执行时忽略新的 alarm，
防止 5 秒设置造成多个采集批次重叠。

## 测试

- 静态清单测试确认不增加权限。
- 单元测试覆盖默认 30 秒、最低 5 秒、分钟迁移和两个字段冲突。
- 契约测试确认 alarm 使用 `refreshSeconds / 60`，不再读取分钟作为正常配置。
- 测试确认并发保护存在，且设置页文案、输入属性与 storage 字段一致。
- 完整 `npm run check` 继续覆盖采集、HTTP、PNG 和 MQTT 链路。

## 风险边界

- 5 秒频率可能触发小红书限流或验证，由用户主动选择，仅建议测试使用。
- Chrome 正式打包分发时可能把周期限制为至少 30 秒；本设计不增加绕过浏览器限制的机制。
- 页面加载和网络耗时可能超过刷新周期，并发保护会跳过重叠轮次。
